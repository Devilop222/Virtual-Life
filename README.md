# 🎮 Legacy Game — میراث

**میراث** یک بازی شبیه‌ساز زندگی و نقش‌آفرینی در بستر تلگرام است که با **TypeScript**، **PostgreSQL** و **Prisma** ساخته شده. در آن شخصیتی می‌سازی که کار می‌کند، درس می‌خواند، ازدواج می‌کند، کسب‌وکار می‌زند و در منطقه‌اش اثر به‌جا می‌گذارد — میراثش از انتخاب‌هایش ساخته می‌شود.

این سند به‌گونه‌ای نوشته شده که حتی بدون دانش برنامه‌نویسی بتوانید پروژه را روی **Railway** راه‌اندازی کنید.

> نام فنی پروژه (مخزن، `package.json` و متغیرهای محیطی) همچنان `virtual-life-bot` است؛ تغییر آن نیازی به بازنشاری GitHub ندارد.

## ⚡ راه‌اندازی سریع روی Railway (Deployment)

### گام ۱ — Push کدها به GitHub
پروژه را در یک مخزن GitHub قرار دهید. ساختار مناسب مخزن:

```
VirtualLife/
├── prisma/
│   ├── migrations/          # دستورات دیتابیس (خودکار اعمال می‌شود)
│   ├── schema.prisma        # تعریف مدل‌های دیتابیس
│   └── seed.ts              # داده‌های اولیه (مهارت‌ها و شغل‌ها)
├── src/                     # کدهای TypeScript ربات
├── tests/                   # تست‌های خودکار
├── Dockerfile               # نحوه ساخت ایمیج
├── package.json             # وابستگی‌ها و دستورات
└── railway.json             # تنظیمات Railway
```

### گام ۲ — ساخت پروژه در Railway
1. وارد [Railway.com](https://railway.com) شوید و با حساب GitHub وارد شوید.
2. دکمه **+ New Project** را بزنید و **Deploy from GitHub repo** را انتخاب کنید.
3. مخزن بازی (مثلاً `VirtualLife`) را انتخاب کنید. Railway به‌صورت خودکار فایل `Dockerfile` را تشخیص می‌دهد.

### گام ۳ — افزودن پایگاه داده PostgreSQL
1. در همان پروژه دکمه **+ Create** را بزنید و **Database ➔ Add PostgreSQL** را انتخاب کنید.
2. Railway یک متغیر `DATABASE_URL` به‌صورت خودکار در اختیارتان می‌گذارد.

### گام ۴ — تنظیم متغیرهای محیطی (Environment Variables)
روی سرویس ربات کلیک کنید، به تب **Variables** بروید و این متغیرها را اضافه کنید:

| متغیر | نمونه مقدار | توضیح |
| :--- | :--- | :--- |
| `BOT_TOKEN` | `123456789:ABCdefGHI...` | توکن ربات از [@BotFather](https://t.me/BotFather) با دستور `/newbot` |
| `DATABASE_URL` | `postgresql://user:pass@host:5432/db` | دکمه **Add Reference** بزنید و `DATABASE_URL` دیتابیس را انتخاب کنید |
| `NODE_ENV` | `production` | محیط اجرای برنامه |

> ⚠️ `PORT` را دستی تنظیم نکنید. Railway به‌صورت خودکار `PORT` را ارائه می‌دهد و برنامه آن را می‌خواند.

### گام ۵ — Deploy
پروژه پس از افزودن متغیرها به‌صورت خودکار Deploy می‌شود. ترتیب اجرا در هنگام استقرار:

1. **Build** — نصب وابستگی‌ها، تولید کلاینت Prisma و ترجمه TypeScript با `npm run build`.
2. **Migration** — اعمال جدول‌های دیتابیس با `npx prisma migrate deploy`.
3. **Start** — اجرای ربات با `node dist/app.js`.

## 📦 راه‌اندازی آفلاین روی سرور شخصی (Daytona و ...)

اگر می‌خواهید ربات را روی یک سرور لینوکس (مثلاً سندباکس Daytona) **بدون دانلود از اینترنت** اجرا کنید،
پوشهٔ `offline-deps` همهٔ پیش‌نیازها (Node.js، وابستگی‌ها، PostgreSQL داخلی) را با خود دارد:

```bash
git clone https://GITHUB_TOKEN@github.com/aminatkh0-ship-it/VirtualLife.git
cd VirtualLife
bash offline-deps/install.sh    # در پایان فقط توکن ربات را از شما می‌خواهد
```

راهنمای کامل، ساخت توکن‌ها و دستورات روزمره (start/stop/status/update): [`offline-deps/README.md`](offline-deps/README.md)

## 🗄️ پایگاه داده (PostgreSQL)

- **تعریف مدل‌ها:** فایل `prisma/schema.prisma`
- **Migrate‌ها:** پوشه `prisma/migrations` شامل دستورات SQL نهایی برای ساخت جدول‌ها
- **اعمال دستی migrate روی یک دیتابیس:**
  ```bash
  DATABASE_URL="postgresql://..." npx prisma migrate deploy
  ```
- **بذر داده‌های اولیه (یک بار پس از اولین migrate):**
  ```bash
  npm run prisma:seed
  ```
- Railway هنگام هر Deploy به‌طور خودکار migrate را اجرا می‌کند؛ نیازی به کار دستی نیست.

## 🔍 بررسی موفقیت Deployment

1. در Railway، روی سرویس کلیک کنید و تب **Deployments** را باز کنید.
2. یک Deploy **Active** (سبز) یعنی موفق؛ نتیجه شروع ربات به شکل زیر در **Logs** دیده می‌شود:
   ```
   Database connected
   Bot @YourBotUsername started
   ```
3. در تلگرام به ربات پیام `/start` بدهید؛ اگر منوی ثبت‌نام باز شد یعنی ربات آنلاین و دیتابیس آماده است.

## 📜 مشاهده Logs

- تب **Deployments** ➔ **View Logs** در Railway.
- لاگ‌ها در محیط تولید به‌صورت JSON ساختاریافته هستند و شامل سطح `info`، `warn` و `error` می‌باشند.
- توکن‌ها و رمزها در لاگ‌ها به‌صورت خودکار `[REDACTED]` می‌شوند.

## 🛠️ اگر Application Crash کرد چه کنم؟

1. به **Logs** سرویس نگاه کنید و خطای `error` را پیدا کنید.
2. رایج‌ترین دلایل:
   - `Invalid environment configuration: BOT_TOKEN is required` → متغیر `BOT_TOKEN` تنظیم نشده است.
   - `Database connection failed` → `DATABASE_URL` اشتباه است یا دیتابیس در دسترس نیست.
   - `P2021 The table ... does not exist` → migrate اجرا نشده؛ دستور `npx prisma migrate deploy` را در ترمینال Railway (تب **Shell**) اجرا کنید.
3. پس از اصلاح، روی دکمه **Deploy** برای Deploy مجدد بزنید یا یک Change را Push کنید.

## 🆕 چگونه یک Update جدید Deploy کنم؟

1. تغییرات را در GitHub روی شاخه `main` (یا شاخه متصل به Railway) **commit** و **push** کنید.
2. Railway به‌صورت خودکار build و migrate و استقرار نسخه جدید را انجام می‌دهد.
3. در تب **Deployments** نتیجه جدید را بررسی کنید.

## 🎮 منوها و تعاملات فارسی ربات

بازی کاملاً **متنی (Text-first)** است؛ کلیدواژهٔ فارسی هر بخش را می‌فرستی و
دکمه‌های Inline زیر پنل‌ها ناوبری را انجام می‌دهند. **Reply Keyboard وجود ندارد**
و تنها دستور بازی `/start` است.

- `/start`:
  - در **چت خصوصی**: اگر شخصیت نداری، ثبت‌نام را شروع می‌کند (انتخاب جنسیت و نوشتن بیوگرافی)؛
    اگر شخصیت داشته باشی، **راهنمای شروع چندصفحه‌ای** باز می‌شود.
  - در **گروه**: اگر فرستنده مدیر گروه باشد، محیط بازی همان گروه را به‌عنوان یک «منطقه» ثبت و راه‌اندازی می‌کند؛
    اگر گروه از قبل راه‌اندازی شده، اطلاعات منطقه را نشان می‌دهد؛ و اگر فرستنده مدیر نباشد و گروه هنوز راه نیفتاده باشد،
    می‌گوید «این گروه هنوز برای بازی راه‌اندازی نشده است».
- با ارسال یکی از این کلمات پنلش باز می‌شود: `شناسنامه`، `کار`، `شغل من`، `کسب و کار`، `بازار`، `تحصیلات`، `خانه`، `بانک`، `دفتر مالی`، `تاریخچه`، `خانواده`، `محل زندگی`، `رتبه`، `اعلان‌ها` و ده‌ها کلمه دیگر (فهرست کامل در پنل راهنما).
- `شناسنامه`: کارت شناسنامه کاربر با **عکس واقعی پروفایل تلگرام** (اگر موجود باشد).
- **Reply پیام دیگران + ارسال `شناسنامه`**: شناسنامه همان شخص نمایش داده می‌شود (رعایت حریم خصوصی).
- `تحصیلات`: ثبت‌نام در دانشگاه، انتخاب رشته و ارتقای مقطع.
- `کار`: کارهای پاره‌وقت در ۱۴ دسته‌بندی با **ظرفیت پویا** (بر اساس تعداد ثبت‌نامی‌های واقعی) و توقف خودکار هنگام خستگی بحرانی + تأسیس کسب‌وکار.
  درآمد = `حقوق پایه × سختی کار × بهره‌وری` و **بهره‌وری** تنها در `src/modules/life/life-core.ts` ساخته می‌شود:
  `توان بدنی (سلامت و خستگی) × مهارتِ همان کار × سابقه × مدرک و هم‌حوزه بودن رشته × سن`.
  همان ضریب، عددِ «بهره‌وری» روی شناسنامه را هم می‌سازد، پس آنچه بازیکن می‌بیند با آنچه می‌گیرد یکی است.
- `خانه`: خرید ملک، استراحت و ریکاوری خستگی.
- `بانک`: افتتاح حساب، واریز/برداشت، سود سپرده و وام با وثیقه.

## 👥 بازی در گروه (Group Play)

بازی اصلی میراث **در گروه** انجام می‌شود؛ چت خصوصی برای ثبت‌نام، دیدن وضعیت شخصی
(شناسنامه، وضعیت، آمار، دفتر مالی، تاریخچه) و لینک دعوت است. اگر کلمه‌ای را در
محیط اشتباه بفرستی، ربات به‌جای سکوت یا خطا، با یک پیام فارسی می‌گوید کجا باید
رفت (سیاست محیط در `src/bot/chat-policy.ts` متمرکز است).

**ترتیب ورود به بازی:**

1. هر کاربر در چت خصوصی `/start` را می‌فرستد و شخصیتش را می‌سازد.
2. مدیر گروه در گروه `/start` را می‌فرستد تا محیط بازی (منطقه) فعال شود.
3. بازیکن ثبت‌شده با اولین فعالیت واقعی در گروه (مثلاً فرستادن «کار») عضو همان
   منطقه می‌شود و اقامت اولیه‌اش ثبت می‌گردد.

گروهی که مدیرش بازی را فعال نکرده باشد، هیچ‌گاه خودش را محیط فعال جلوه نمی‌دهد؛
بخش‌های گروهی بازی در آن پیام «راه‌اندازی نشده» نشان می‌دهند.

برای اینکه ربات پیام‌های متنی گروه را ببیند:

1. به [@BotFather](https://t.me/BotFather) پیام بدهید.
2. `/mybots` → ربات را انتخاب کنید.
3. **Bot Settings** → **Group Privacy** → **Turn off**.
   - با Privacy Mode روشن، تلگرام فقط Reply و Mention و Command ها را به ربات می‌فرستد و ربات متن «خانه» را نمی‌بیند. خاموش کردن آن برای بازی متنی در گروه **الزامی** است.
4. (اختیاری) ربات را به‌عنوان **ادمین** گروه اضافه کنید تا تعداد اعضا را شمارش کند؛ برای خواندن متن‌ها لازم نیست.

ترتیب کلی در گروه:
```
User ارسال "خانه"
   ↓
Bot پنل خانه همان کاربر را در Reply همان پیام باز می‌کند
```
اگر کاربر روی پیام شخص دیگری Reply کند و بنویسد `شناسنامه`، پنل همان شخص دیگر نمایش داده می‌شود (در صورت عمومی بودن اطلاعات).

## 🛡️ پنل ادمین

فهرست ادمین‌ها در جدول `bot_admins` ذخیره می‌شود؛ هیچ متغیر محیطی‌ای برای آن وجود ندارد.
در اولین اجرا دو ادمین اولیه به‌صورت Idempotent ساخته می‌شوند: `6910416744` (ادمین اصلی/OWNER)
و `8369939024` (ادمین دوم).

| عبارت | چه می‌کند | چه کسی |
| :--- | :--- | :--- |
| `/admin_help` | راهنمای چندصفحه‌ای و تعاملیِ تمام ابزارهای واقعی مدیریت را باز می‌کند | هر ادمین فعال؛ کاربر عادی کاملاً بی‌صدا |
| `پنل ادمین` | داشبورد مدیریت را در Reply همان پیام باز می‌کند | هر ادمین فعال |
| `ادمین ها` (یا `ادمین‌ها`) | فهرست کامل ادمین‌ها | فقط ادمین اصلی |
| `اضافه ادمین` | روی پیام کاربر ریپلای کن و این عبارت را بفرست | فقط ادمین اصلی |
| `حذف ادمین` | روی پیام همان ادمین ریپلای کن و این عبارت را بفرست | فقط ادمین اصلی |

- این عبارت‌ها در چت خصوصی و در هر گروهی که ربات عضو است کار می‌کنند.
- کاربر غیرادمین **هیچ** پاسخی نمی‌گیرد؛ حتی یک پیام «دسترسی نداری».
- ناوبری با ویرایش همان پیام انجام می‌شود (یک اقدام = یک پنل = یک پیام).
- شامل: داشبورد آمار، بازیکنان و گروه‌ها با صفحه‌بندی و جست‌وجو، مدیریت اقتصاد
  (افزودن/کسر/تنظیم موجودی)، سلامت/خستگی/تجربه، تحصیل و مهارت‌ها، وضعیت حساب،
  توقف نوبت کاری، صفرکردن استریک و بازنشانی وضعیت، همگام‌سازی گروه با تلگرام
  و گزارش اقدامات.
- هر عملیات مخرب یک مرحلهٔ تأیید دارد و همهٔ تغییرات در جدول `AdminLog`
  با مقدار قبل و بعد ثبت می‌شود.
- `حذف ادمین` فقط دسترسی مدیریت را می‌گیرد؛ حساب بازیکن و داده‌های بازی او دست‌نخورده می‌ماند.
- ادمین اصلی حذف‌شدنی نیست.
